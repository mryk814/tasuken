# Issues #481 / #482 の確認手順

## 自動確認

```bash
npm run typecheck
npm run build
npm test
```

## #481 の実画面確認

- Theme の「報告書・重要文書」で Prompt を追加し、保存後に「コピー」と「編集」が別操作として表示される。
- Chat Refs のURL付き行から「元チャットを開く」を押せる。行編集・続き追加・会話ログ・Archive と誤爆しない。
- 新しい付箋は「常に手前に表示」がOFF。小さい付箋でも色メニュー最下段のグレーを選べ、長文・改行・コード相当の入力が横にはみ出さない。
- 付箋一覧では、ピン状態と独立して色を変更でき、色フィルターは既定で全色表示。各カードを個別に折りたたみ、長文は上限付き表示から全文表示へ切り替えられる。
- Task Drawer の Checklist 末尾で Enter を連続入力しても、保存後に入力欄・Drawerのスクロール位置が先頭へ戻らない。
- Focus終了時は Task完了がON、ScratchpadのNote化がOFF。Note化は明示した場合だけ行う。
- Today の「今日やること」行から、対象TaskのFocusを一発で開始できる。Today miniの完了マークはTaskenのアクセント色で丸く表示される。
- Settings の Direct shortcut は Windows では `Ctrl+Shift+Space` 形式、Macでは記号形式で表示される。保存値は accelerator 構文のまま維持する。
- Chat Refs の親が先、続きが後に並び、段下げは保存された `parent_resource_id` の深さだけで決まる。矢印を非表示にしても行本文の位置は変わらない。

## #482 の診断

診断は既定OFFで、通常動作ではタイマー・Observerを起動しません。RendererのDevTools Consoleで次を実行して再読み込みすると、固定イベント種別・経過時間・概算ヒープ量だけが `[tasken:performance]` に出ます。

```js
localStorage.setItem("tasken.performanceDiagnostics", "1");
location.reload();
```

Main側は `TASKEN_PERF_DIAGNOSTICS=1` を付けた起動時だけイベントループ遅延と `workspace_load` の所要時間・結果サイズ（KB）を記録します。本文、タイトル、URL、パス、秘密情報は記録しません。確認後はRendererのlocalStorageを削除し、Mainは環境変数を外して通常起動へ戻します。

重点操作は Today / Timeline / Notes / Chat Refs の切替、Drawerの開閉とChecklist連続保存、長文Note編集、Theme往復、Stickyの複数開閉です。ログが出た場合は操作と固定イベント種別・時間だけを対応付けます。

## 静的監査結果

- 同期I/Oは添付・Import/Export・Snapshotなどの境界に集中しており、通常のRenderer操作から直接呼ぶ経路は確認できませんでした。
- 主なタイマーとイベントリスナーには解除処理があり、Workspace再読込はIPCの `workspaceLoad` から `WorkspaceService.loadWorkspace` に集約されています。
- Chat Refs は行ごとの親Map再生成をやめ、一覧単位で深さを一括計算するようにしました。診断ログでのアプリ全体の重さの切り分けは引き続き上記手順で行います。
