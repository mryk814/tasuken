## 1. この画面が答える問い

**前回から何が変わり、今どこに反応するか。**

FeedはTaskの一覧でも管理画面でもない。既存のcanonical dataから作る **attention projection** であり、
Task・Receipt・Proposalの正本を複製しない。Task全件、毎回同じ期限警告、raw logは主役にしない。

## 2. 責務の比較

同じデータを3面以上に同時表示しない。それぞれが答える問いを分ける。

| 画面         | 答える問い                                 | 主な操作                               | 主役にしない情報                       |
| ------------ | ------------------------------------------ | -------------------------------------- | -------------------------------------- |
| Feed         | 前回から何が変わり、今どこに反応するか     | 開く、回答、成果確認、今日扱う         | Task全件、毎回同じ期限警告、raw log    |
| Today        | 今日、自分が何を実行するか                 | 着手、完了、扱う日の変更               | AIの全進捗、接続管理、未整理入力の全件 |
| Agent Desk   | 任せた仕事がどこまで進み、何を待っているか | 回答、成果確認、報告採用、委任内容確認 | token数、モデル比較、実行コンソール    |
| ToDo / Theme | 仕事全体の内容・所属・日程をどう管理するか | 編集、分類、計画、検索                 | Feed用の独自Taskコピー                 |
| Activity     | いつ何が起き、どの記録を根拠に振り返るか   | 日時から記録へ移動                     | 現在の判断待ちの別管理                 |
| Inbox        | 残した入力をどう整理するか                 | Task化、Note化、整理                   | Feedの既読処理                         |

FeedとAgent Deskの判断操作は、**同じ要対応項目と同じ詳細コンポーネントを開く**。
Todayには必要なら「AIの対応待ち N件」という入口だけを置き、同じ質問カードを三重に並べない。
要対応件数のbadgeはAgent Deskへ集約し、Feedと二重に付けない。

## 3. Tasken固有のvisual grammar（1枚に固定）

```text
[出所]                                            12分前
見出し（必要な行動が分かる）                      [状態]  [AI提案]
本文の要旨（1〜2行）
締切 9月25日   高分子材料評価 › 粘度測定の条件を決める
[主要操作] [補助操作]
──────────────────────────────────────────────
```

Xから借りるのは**行の文法だけ**。次は持ち込まない。

| 借りる                                    | 持ち込まない                                   |
| ----------------------------------------- | ---------------------------------------------- |
| 1 item = 小さい情報単位                   | 推薦順位、反応数、閲覧時間の最大化             |
| 出所と相対時刻を本文の近くに置く          | 人物の人格化、avatar中心のレイアウト           |
| 行区切り中心の密度。1行を丸い箱に分けない | 無限スクロール                                 |
| 開いて深掘りする                          | `Like`相当の軽い反応を意味のない賛同にすること |

### 見た目の規則

| 項目       | 規則                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| 面         | 白い連続面と横罫線。行ごとの丸い箱に分けない                                              |
| 文字       | 本文 `--text-base`(14px)、補足 `--text-sm`(13px)、行見出し `--text-lg`(16px)              |
| 数字       | 時刻・件数は `tabular-nums`                                                               |
| 密度       | 上下14px。見出し1行＋要旨1〜2行＋対象1行＋操作1行。固定高で文章を切らない                 |
| 操作数     | 常時表示は主要1つと補助1つ。行のbuttonは最大4個（design-guide §18b）                      |
| 主操作の色 | **burgundyの塗りは、開いている回答・確認フォームの主操作だけ。** 全行へ強い塗りを並べない |
| 状態       | `--color-status-*` を使い、**色だけでなく文字ラベルを必ず併記する**                       |
| AIの区別   | `--action-ai-*` と「AI提案」「AI要約」の文字ラベル。事実か提案かを色だけで判定させない    |
| 選択       | 淡い背景とアクセントバー。focusは別に `--focus-ring` で示す                               |
| 動き       | 新着の挿入・点滅・連続する読み上げをしない。`prefers-reduced-motion` を尊重する           |

本文は選択できる。行全体を巨大な `button` で囲まず、見出しの開く操作と、回答などの操作領域を分ける。

## 4. 5種類のfixture

すべて架空の研究業務データ。出所のラベルだけを差し替えた同じ文章を並べず、**行動の違い**を検証する。

| 種類             | 見出しの例                     | 状態     | 常時表示する操作         | 詳細で確認するもの                         | 生成ラベル |
| ---------------- | ------------------------------ | -------- | ------------------------ | ------------------------------------------ | ---------- |
| 今日扱うTask     | 引張試験の結果を比較する       | 今日     | Taskを開く／扱う日を変更 | Task本文、チェック項目、扱う日と締切       | なし       |
| 停滞に関する提案 | 比較条件を先に揃える案         | AI提案   | 提案を見る／今回は見送る | 根拠となる更新時刻、提案範囲、採用前の差分 | AI提案     |
| 人間への質問     | 測定温度を選んでください       | 回答待ち | 回答する／後で見る       | 選択肢、推奨理由、作業単位                 | なし       |
| 成果確認         | 比較表の作成報告が届きました   | 成果確認 | 成果を確認／Taskを開く   | 成果、検証根拠、未確認事項、採用範囲       | なし       |
| 過去の文脈       | この条件を選んだ記録があります | 記録     | 記録を開く／今回は見送る | 元の記述、記録日、Taskとの関係             | AI要約     |

### 生成ラベルの規則

- 「3日間更新がない」は**観測できる事実**。「仕事が止まっている」は**推測**。事実だけを書き、推測は提案として出す。
- AIによる提案には「AI提案」、過去の文章を要約した場合には「AI要約」を付ける。
- **通常のTaskや人が書いた過去の判断に生成ラベルを付けない。**
- AI要約には原文への参照（記録日）を必ず残す。
- 「過去の自分」という架空のactorを増やさず、`自分の記録` と記録日を使う。

## 5. 操作の意味

| 表示名       | 対象と結果                               | 変えてはいけないもの             |
| ------------ | ---------------------------------------- | -------------------------------- |
| 今日扱う     | Taskの `today_date` を今日にする         | 締切、実行主体                   |
| 扱う日を変更 | Taskを扱う日を選ぶ                       | Scheduleの締切                   |
| 後で見る     | この質問や報告を再表示する日時を選ぶ     | Taskの日程、質問の未解決状態     |
| 今回は見送る | 任意の提案や参考情報を今回のFeedから外す | Task、Note、Proposalの正式な採否 |
| 回答する     | 特定の質問へ人間の返答を保存する         | Task本文の全文、別の質問         |
| 提案を見る   | 既存Proposal previewを開く               | 開いただけでの正式データ更新     |
| 成果を確認   | ReceiptとProposalの詳細を開く            | 開いただけでの採用やTask完了     |
| 完了にする   | 人間がTaskの完了を明示する               | 同じ見た目の「既読」への置換     |

- **「後で見る」は未解決件数を減らさない。** 先送りであり解決ではない。対応待ちタブで「今 N件／後で M件」と示す。
- 初期Feedでは完了をすべての行に置かない。日付操作の誤解を減らしてから直接完了を追加する。
- 既読、詳細を開いたこと、保留、回答済み、採用済みを**別の意味**として扱う。
- プロトタイプでは保存せず、回答・見送り・後で見るは画面内の状態だけを変える。

## 6. 並び順の規則

「今見る」は次の段階順。AIによる非公開スコアを導入しない。

1. 保留していない人間への質問と判断依頼
2. 未処理の成果確認と変更Proposal
3. 今日扱うTaskに関する新しい変化
4. 任意の提案と関連記録

- **同じ段階では人が設定した期限を優先し、次に受信の古いものを先にする。**
- AIの自己申告による緊急度だけで順位やTaskのpriorityを変えない。
- 「最近の更新」は受信の新しい順にし、判断待ちの重要順と混ぜない。
- 任意の提案と関連記録は初期値として**一日合計5件まで**。要対応項目をこの上限で隠さない。

### 表示理由

すべての行が「なぜ今これを出したか」を説明できる。詳細に `表示理由:` として出す。
例: 「回答が届くまで作業を再開できません。」「最終更新が3日前です。停滞かどうかは分かりません。」

将来rankingを変える場合も、**説明できない要素を順位に混ぜない。**

### 終わりと新着

- 初回は20行を表示し、続きは「次の20件を表示」で開く。
- 末尾は「今確認する更新は以上です」。後で見る項目があれば「後で見る N件」を併記する。
- **情報を読んだだけで「すべて対応済み」と表示しない。**
- 閲覧中に新着を先頭挿入しない。固定したヘッダー領域に「新しい更新 N件」を出し、
  **人が反映するまで行の順序とスクロールの基点を動かさない。**
- Feedを開くたびにAIが新しい文章を生成して空白を埋めない。

## 7. 幅ごとの構成

[docs/responsive-layout.md](./responsive-layout.md) を優先する。判定はウィンドウ幅ではなく実際のpanel幅で行う。

| 実効の作業幅 | 構成                                                                      |
| ------------ | ------------------------------------------------------------------------- |
| 1180px以上   | 読み幅720pxのFeedと、380pxの右詳細スロットを並べる。右端に余白を残す      |
| 1180px未満   | Feedは1列。詳細は選んだときだけ右から重ね、中央の幅とスクロールを変えない |
| 未選択       | 右側は静かな空間。全体指標やおすすめで埋めない                            |

- 中央本文を画面幅いっぱいに伸ばさない。
- 狭幅では右詳細を重ね、`Escape` と「閉じる」で**起点の行へfocusを戻す**。
- 閉じる操作は下書きの保存であり、回答の送信でもProposal採用でもない。
- 980×680（最小ウィンドウ）と表示倍率1.3でも操作が押し出されない。

## 8. 検証

```powershell
rtk npm run build
rtk npm run audit:feed
rtk node scripts/run-electron-node.mjs --test tests/feed-fixtures.test.mjs
```

`audit:feed` は隔離した一時userDataでアプリを起動し、1536×960／1280×800／980×680で
行の描画、横スクロール、縦積み、詳細スロットの出方、`Escape` 後のfocus復帰、
「後で見る」で要対応件数が変わらないことを実測する。スクリーンショットは `output/playwright/feed-audit` へ出す。
