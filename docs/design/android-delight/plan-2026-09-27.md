# Android Tasken：触りたくなる仕事の手帳

2026-09-27 / 方向性提案。初期実装単位（Todayの情報階層・Task完了の反応・保存時フィードバック）は実装済み。Recallの手帳化とAI面の刷新は未実装。

## 狙い

追加の画面資料：[ウィジェット・ToDo・AI成果確認・記録のコンセプト画像](README.md)。後続検討用で、最初の実装単位は変更しない。

「機能がある」から「ちょっと開いて、ひとつ残したくなる」へ。
ここでいうドパガキ仕様は、操作の手応えと、仕事が目に見えて積み上がる楽しさを強めることと解釈する。
研究ではTaskを完了できない日にも価値のある観察が残るため、完了数だけをごほうびにしない。
脳内物質や習慣形成への効果を保証する提案ではなく、実際に触って評価する体験仮説である。

**推す方向：研究の手帳が、触るたびに育つ。**
開く → 今日の仕事が見える → ひとつ記録する／完了する → 手元に残った手応え → あとで眺める、という短い循環を作る。

## 比較した方向

| 案                 | 楽しさ                                 | Taskenとの相性                                         | 判断                         |
| ------------------ | -------------------------------------- | ------------------------------------------------------ | ---------------------------- |
| アーケード型       | XP、連続達成、派手な完了演出           | 小タスクの量を増やす誘因が強く、研究の進展と一致しない | 今回は採らない               |
| 育成キャラ型       | 記録でペットや庭が育つ                 | 愛着は狙えるが、資産・育成ルール・日々の管理が必要     | 別の大きな方向転換として保留 |
| 手帳コレクション型 | 自分の観察が読み返したくなる一枚になる | 作業記録・Theme・Recallを直接活かせる                  | 推奨                         |

楽しさの強さは、手帳型を基盤に「押したときの小さな弾み」「保存時の印」「記録が収まる動き」で出す。
画面を開いている間ずっと動かすのではなく、本人の操作に反応する。

## 3つの場面

### 1. 開く：今日の仕事にすぐ戻れる

- 上部は日付とToday。正常な同期情報は短くまとめ、詳細は状態表示から開く。
- 今日のTaskを既存順で表示する。最初の一件はタイトルとChecklistを読みやすく見せるが、新しい「おすすめ」や自動優先順位は作らない。
- 完了操作は右端。長いタイトルは折り返し、タッチ領域を確保する。
- 本文中に「今日残したもの」を置き、最新の作業記録を最大2件、本文の短い抜粋で見せる。今日のTaskが多いときは一行の入口に縮める。
- 追加・音声は現在の右下導線を継承。空のTodayでも、記録を書く／Taskを追加する入口がある。
- オフラインを毎回失敗扱いにしない。「端末に保存済み」「PCへ未反映」を区別する。競合や保存失敗は目立つ操作付き表示を保つ。

### 2. 残す：入力が、自分の仕事の一片になる

- 作業記録の保存とTask追加は、既存の意味と保存経路を維持する。同じ成功演出を使っても勝手に相互変換しない。
- 音声入力中の反応、認識した文字、編集中、保存済みが見分けられる。入力は随時修正できる。
- AI整理は採用前の案であることを保つ。整理成功の演出を正式保存の演出と混ぜない。
- 端末への永続保存成功後、保存印と短い触覚を一度だけ出す。リトライ、再描画、PC同期の受信で再演しない。
- Taskの完了時は右端のチェックが短く反応する。行がすぐ飛んで次のTaskを誤タップさせないよう、位置を保って状態を変える。
- Undoは既存の取り消し契約で成立する操作だけに出す。見た目だけの「元に戻す」は置かない。
- 保存中は「保存しています」、端末保存後は「端末に保存しました」、未同期なら「PCへ未反映」を併記する。

### 3. 眺める：成果と考えた過程が、ちゃんと残っている

- 既存Recallを手帳のページとして整える。日付、Theme名、本文、記録種別の順で読めるようにする。
- 作業記録・Task完了・未整理・AI報告・本人による採用を区別する。AIが働いた件数を本人の達成として足さない。
- 「温度条件の違いを記録」のような架空の研究内容をデザイン例に使う。実装時は実際の本文を抜粋し、架空の成果や評価を生成しない。
- 紙の重なりは記録カードの端にだけ使う。全文を囲む装飾、常時アニメーション、巨大な達成率リングは増やさない。
- 週の日付列から既存の日別記録へ移動する。休んだ日に欠損・失敗の印を付けない。
- 取得途中・未取得は空の日と区別する。完全取得前の件数を一日の確定総数として見せない。

## 見た目と動きの設計

| 要素             | 指定                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 色               | 既存トークンのburgundy `#8A2F3B`、背景 `#F4EEEC`、白い面、本文 `#26201E`、枠 `#DCC1C4`、保存成功 `#2E8B57`。ダークは既存dark値を使用 |
| 文字             | 共通標準のNunito系見出し・数字とNoto Sans JP系本文を基準に、Android既存フォント実装に合わせる。数字は桁を揃える                      |
| 面               | 既存の7〜10相当の控えめな角丸。本文を主役にし、紙の端の表現を記録部分に限定                                                          |
| 動き             | 既存120ms / 180msトークンを出発点に、押下・チェック・保存印を試作。演出完了を操作の待ち時間にしない                                  |
| 触覚             | 保存／完了の短い確認を候補にする。端末設定に従い、音は既定で追加しない                                                               |
| アクセシビリティ | 色以外でも状態を伝える。動きを減らす設定では静的な印と文字。TalkBack、文字拡大、キーボード操作を別途確認                             |
| 片手操作         | 頻用操作は右下。S23の実測範囲とFoldカバーの差を使い、IME・ナビ領域込みで位置を確認                                                   |

バーガンディの手帳は既存のブランドから導いた選択であり、新しい装飾テーマへの全面移行ではない。
生成画像の字形、寸法、色は参考表現。実装時の正本は既存トークンと本計画の状態契約とする。

## 評価と検証の計画

同じ架空データで、変更前後の「開く→完了」「音声→修正→保存」「昨日の記録を探す」を比較する。
使いたさは本人の短い試用で評価する。滞在時間や起動回数を増やすこと自体を成功条件にしない。

- まず静止案で、Taskと記録が見つかるか、紙表現が邪魔でないかを確認する。
- 次に隔離データで動きと触覚を試す。Foldカバーで右手操作、S23で実機操作、展開時の一覧・詳細を確認する。
- 読み込み中、空、保存失敗、成功に加え、未同期、競合、長文、文字拡大、ダーク、IME表示、動き抑制を確認する。
- スクロール中に完了しても位置が飛ばない。シートを閉じたら元の位置とfocusに戻る。失敗後も全文が残る。
- 日付をまたぐ記録、未取得日、部分取得、同じ記録の同期合流、端末再起動後を既存Recall境界で検証する。
- 実装対象に応じて既存Today／WorkLog／Recallのunit・instrumentationを選ぶ。ビルドや実機テストを今回実行したことにはしない。
- 3〜5日の本人試用で「もう一件残したくなるか」「演出がうるさくないか」「過去の記録を読みたくなるか」を確認する。外部分析サービスは追加しない。
