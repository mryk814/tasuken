# Todayの日付操作（#454前半）

同じ「あとで」という語で、三つの保存先を動かさない。
Taskenの日付操作は**対象ごとに別の操作**とし、表示名でも保存先でも区別する。

- 用語: [glossary.md](./glossary.md)
- 実装: `src/renderer/src/features/workspace/pages/TodayPage.tsx`

---

## 1. 三つの操作

| 表示名           | 変えるもの               | 変えないもの                   | 入口                          |
| ---------------- | ------------------------ | ------------------------------ | ----------------------------- |
| **扱う日を変更** | `Task.today_date` のみ   | Scheduleの締切、実施期間、状態 | Todayの各Task行               |
| **締切を変更**   | `Schedule.end_date` など | `today_date`                   | Task詳細の予定編集            |
| **後で見る**     | 質問・報告の再表示日時   | Taskの日程、質問の未解決状態   | Feed / Agent Desk（#596以降） |

`today_date` は「利用者が今日扱うと選んだ日」であり、**期限ではない**。
`Schedule.end_date` が締切の正本で、既存データの意味を変えない。
ToDoの「今日の予定」ボタンの選択印は `today_date = 今日` の場合だけ表示する。追加・解除は `today_date` だけを更新し、Scheduleの開始日・締切・実施期間を変更しない。
ToDoの「今日」フィルターと件数は、上部Todayミニと同じ共通selectorの対象を使う。期限が今日のTaskは対象に含めるが、期間の開始日だけでは今日選択済みと扱わない。

## 2. 「扱う日を変更」の選択肢

Task行の「扱う日」から開く。**「来週」は実際の日付を併記する。**

| 選択肢           | 結果                                    |
| ---------------- | --------------------------------------- |
| 今日             | `today_date = 今日`                     |
| 明日             | `today_date = 明日`                     |
| 来週（9月27日）  | `today_date = 7日後`。日付を併記する    |
| 日付を選ぶ       | 選んだ日を `today_date` にする          |
| 今日の選択を外す | `today_date = null`（今日の選択を解除） |

保存後の説明は**期限が関係する場合だけ**短く添える。

```text
9月21日に扱います。 締切は9月19日のままです。
```

締切が動いていないことを毎回説明しない。期限がないTaskでは日付だけを伝える。

## 3. Undo

日付操作は取り消せる。トーストに「元に戻す」を出し、**保存前の `today_date` へ戻す**。

- 取り消しは保存後に押されるため、押した時点の正本を読み直してから書き戻す。
  保存前の値で書くと版競合（`保存対象が更新済みです`）で失敗する。
- 取り消しで動くのは `today_date` だけ。締切は最初から動いていない。
- トーストは取り消せる操作のときだけ長め（4.5秒）に残す。

## 4. 締切の受け皿

「期限の確認」セクションは2026-09-24にTodayから撤去した。撤去後、締切の受け皿は共通selectorの意味に従って分かれる。

- **締切が今日のTask**は、`today_date` を明示していなくても共通selectorのdueとして**今日やること（実行一覧）に出る**。
- **締切が過去のTask**は実行一覧から外れ、候補棚「期限切れ」に出る。**未来に回したTaskも同様**に実行一覧から外れ、存在を隠さず期限切れレーンに残る。
- 実行一覧と候補棚で**同じTaskを丸ごと二重表示しない**。
- 「明日扱う」を押して扱う日が未来へ動いても、**締切は当日であり続けるため当日の実行一覧から消えない**。扱う日の選択が実行され先の日にそのTaskを明示的に出す。締切が未来のTaskは、扱う日を動かすと実行一覧から外れる。
- 実行一覧・候補棚に出すのはTaskだけ。Waitingとマイルストーンは従来の枠に残す。

## 5. 「明日扱う」と「完了」

「明日扱う」は `today_date` を明日にするだけ。**締切も状態も変えない。**
期限を過ぎたまま翌日へ回す判断は利用者のもので、Taskenは期限違反として数えない。

## 6. 開いたままの日付切替と保存中表示（#685 / #684）

Taskenを閉じずに日付を跨いでも、Today・Sidebarの件数・候補棚・次にやることが当日の表示へ切り替わる。

- 本体Todayと Sidebar は `useCurrentLocalDate()`（`lib/currentLocalDate.ts`）でローカル日付を購読する。
  60秒ごとの確認に加え、window focus・`visibilitychange`・`pageshow` で照合する。スリープ中にtimerが走らなくても、復帰時に揃う。
- 日付が同じなら再描画しない。timerは購読者が何人でも一つで、購読がなくなれば止める。
- 前面Todayミニウィンドウは以前からfocus・表示復帰・60秒ごとの確認でMainの `selectTodayTasks` を読み直している。本体と同じselectorを使う。
- 日付切替で `today_date`・`Schedule.end_date` は書き換えない。表示の投影だけを作り直す。

Today一覧の投影は `buildTodayPageProjection(domain, today)`（`lib/dailyPlanning.ts`）にまとめ、Domainか日付が変わったときだけ作り直す。
入力欄・drawer・トーストなどのローカルstateでは全Taskを走査しない。

完了・チェックリスト・扱う日・今日の予定・候補棚からの移動は、押した直後に行を処理中（`aria-busy`、破線の完了丸）にする。
保存が確定するまで同じ行への操作は受け付けず、古い版での二重保存を防ぐ。完了表示は保存後のDomainから決め、保存前に完了したとは見せない。
保存に失敗したら行は保存前の表示のまま残り、理由はトーストで知らせる。

## 7. 検証

```powershell
rtk npm run build
rtk npm run audit:today-dates
rtk node scripts/run-electron-node.mjs --test tests/today-ia.test.mjs
```

`audit:today-dates` は一時userDataへ架空のTaskとScheduleを仕込んでからアプリを起動し、
締切当日のTaskが実行一覧に出ること、締切が過去のTaskが候補棚「期限切れ」に置かれること、
`today_date` だけが変わること、締切が動かないこと、Undoで戻ること、980×680で横スクロールが出ないことを実測する。
スクリーンショットは `output/playwright/today-date-audit` へ出す。
