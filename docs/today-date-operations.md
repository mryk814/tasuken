# Todayの日付操作（#454前半）

同じ「あとで」という語で、三つの保存先を動かさない。
Taskenの日付操作は**対象ごとに別の操作**とし、表示名でも保存先でも区別する。

- 全体の設計: [issue-design-plan-2026-09-20.md](./issue-design-plan-2026-09-20.md)「Todayの具体設計」
- 用語: [glossary.md](./glossary.md)
- 実装: `src/renderer/src/features/workspace/pages/TodayPage.tsx`

---

## 1. 三つの操作

| 表示名           | 変えるもの               | 変えないもの                   | 入口                          |
| ---------------- | ------------------------ | ------------------------------ | ----------------------------- |
| **扱う日を変更** | `Task.today_date` のみ   | Scheduleの締切、実施期間、状態 | Todayの各Task行               |
| **締切を変更**   | `Schedule.end_date` など | `today_date`                   | Task詳細の予定編集            |
| **後で見る**     | 質問・報告の再表示日時   | Taskの日程、質問の未解決状態   | Feed / Agent Desk（#596以降） |

`today_date` は「利用者が今日扱うと選んだ日」であり、**期限ではない**。
`Schedule.end_date` が締切の正本で、既存データの意味を変えない。

## 2. 「扱う日を変更」の選択肢

Task行の「扱う日」から開く。**「来週」は実際の日付を併記する。**

| 選択肢           | 結果                                    |
| ---------------- | --------------------------------------- |
| 今日             | `today_date = 今日`                     |
| 明日             | `today_date = 明日`                     |
| 来週（9月27日）  | `today_date = 7日後`。日付を併記する    |
| 日付を選ぶ       | 選んだ日を `today_date` にする          |
| 今日の選択を外す | `today_date = null`（今日の選択を解除） |

保存後の説明は**期限が関係する場合だけ**短く添える。

```text
9月21日に扱います。 締切は9月19日のままです。
```

締切が動いていないことを毎回説明しない。期限がないTaskでは日付だけを伝える。

## 3. Undo

日付操作は取り消せる。トーストに「元に戻す」を出し、**保存前の `today_date` へ戻す**。

- 取り消しは保存後に押されるため、押した時点の正本を読み直してから書き戻す。
  保存前の値で書くと版競合（`保存対象が更新済みです`）で失敗する。
- 取り消しで動くのは `today_date` だけ。締切は最初から動いていない。
- トーストは取り消せる操作のときだけ長め（4.5秒）に残す。

## 4. 期限の確認

締切が今日以前で、**今日扱うと明示していない**Taskは「期限の確認」に置く。

```text
期限の確認 2
  評価条件の回答をまとめる    締切 2026/09/19／2026/09/21扱う    [明日扱う]
  劣化試験の計画を立てる      締切 2026/09/19／2026/09/21扱う    [明日扱う]
```

- 未来に回した期限超過Taskは実行一覧から外すが、**存在を隠さない**。
- 今日が期限のTaskも同じ規則で、今日扱うと明示していなければ期限の確認へ置く。
- 実行一覧・候補棚の期限切れレーンと**同じTaskを丸ごと二重表示しない**。
  候補棚からは外し、件数と行は「期限の確認」に集約する。
- ここに出すのはTaskだけ。Waitingとマイルストーンは従来の枠に残す。

## 5. 「明日扱う」と「完了」

「明日扱う」は `today_date` を明日にするだけ。**締切も状態も変えない。**
期限を過ぎたまま翌日へ回す判断は利用者のもので、Taskenは期限違反として数えない。

## 6. 検証

```powershell
rtk npm run build
rtk npm run audit:today-dates
rtk node scripts/run-electron-node.mjs --test tests/today-ia.test.mjs
```

`audit:today-dates` は一時userDataへ架空のTaskとScheduleを仕込んでからアプリを起動し、
実行一覧と「期限の確認」の重複、`today_date` だけが変わること、締切が動かないこと、
Undoで戻ること、980×680で横スクロールが出ないことを実測する。
スクリーンショットは `output/playwright/today-date-audit` へ出す。
