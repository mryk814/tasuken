# 作業の記録をOneDriveから振り返る

2026-09-05の利用者との確認を反映する。
Taskenの目的は、ローカルで何を試し、何が分かり、何が残ったかを記録し、メールやTeamsの情報と合わせて後から振り返れるようにすることである。
利用者はAI Packを使用していない。
今回の開発では、通常の成果文書とActivityの日誌を中心に据える。

## 保存先ごとの役割

| 保存するもの                     | 現在の保存経路                                                  | 用途                                                                   |
| -------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Task・Noteの管理情報、履歴、設定 | 各端末のuserData配下のSQLite                                    | アプリが管理する正式データ。検索向けの文章ではない                     |
| 端末間の変更差分                 | `sharedSyncDirectory/devices/`                                  | SQLite間の同期用。Copilotに読ませる成果物とは分ける                    |
| 通常NoteのMarkdownと成果ファイル | `artifactDirectory`配下のTheme Notes等、または選択した出力先    | 人が読み、外部から参照する文書。canonical Markdownの既存契約を維持する |
| 日ごとのActivity Markdown        | 個別設定した`activityLogDirectory`、未指定ならRootの`Activity/` | 公開してよい作業と結果を日付から振り返るための文章                     |
| Theme AI Pack                    | 既存の明示的な生成操作                                          | 任意機能。通常の記録・日誌出力の必須段階にはしない                     |

RootがOneDrive上なら、そこへ保存された文書はOneDriveへの同期対象になる。
同期用フォルダと読ませる文書のフォルダは役割が違うため、同じ設定として扱わない。
今回は保存場所の移動、既存ファイルの削除、Boxへの同期先変更を行わない。

## 今回直す日常の経路

1. **ローカル履歴と公開用日誌を分ける。** Debrief画面は個人用履歴を表示する。コピー・手動出力・自動出力は同じM365用の生成処理を使い、現在の項目・Theme・全体の公開範囲を確認する。除外は件数で示し、非公開の題名や本文を説明へ混ぜない。
2. **定時後の作業を翌日にも反映する。** 当日は指定時刻に暫定出力し、翌日に同じファイルへ再出力する。停止中の未確定日も順番に補完する。出力成功後だけ確定日を保存し、失敗時は再試行対象を残す。
3. **採用したAIの作業結果を日誌へ出す。** Taskと受入イベントのReceipt IDが一致する報告だけを、受入日の「採用済みの作業結果」へ載せる。結果・実施項目・変更物・検証・残作業を区別し、内部の実行情報や資格情報を本文へ転記しない。

公開可否は現在の設定で判定する。
過去の公開Themeに所属していたことだけを理由に、現在非公開のTaskを再公開しない。
AIセッションは一続きの文章なので、所属Themeと関連するTask・活動に非公開項目が混ざる場合や所属が確認できない場合は、セッション全体を除外する。
AIセッションの終了報告と、人が採用したTaskの完了報告は別の記録として表示する。

新しい確定日の設定は`activityLogLastFinalizedDate`。
従来の当日出力済み設定`activityLogLastAutoExportDate`を保持し、初回は従来最後に出した日を確定し直す。
同じ日の再出力は既存の日誌ファイルを更新する。
既に外へ出した過去の全ファイルを一括回収する機能ではない。
公開設定を変更した過去の日誌は、該当日を選んで手動出力すると現在の設定で作り直せる。

## 既存機能を見直す判断

AI Packは今回拡張しない。
削除する前に、通常Noteの保存・Activityの日誌・成果への参照だけで必要な振り返りが成立するかを見る。
既存の出力物や利用可能なデータを消すことは、使っていない操作を整理することとは分けて扱う。

次に確認すべき点は、通常Noteの`canonical_markdown`保存先から日誌の成果参照への接続である。
現在のActivityの参照は`canonical_ref(s)`を中心に扱い、通常保存のbindingだけでは辿れない可能性がある。
これは今回の3点とは別の残作業として記録する。
必要なのは新しいパック生成ではなく、保存した成果文書へ既存の記録から戻れる経路である。

## 検証境界

実OneDriveやM365 Copilotへのアクセス・実検索は今回の対象外である。
