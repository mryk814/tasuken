# Androidの端末内検索

ToDoの既存検索欄の下にある「端末内の記録を検索」から開く。
検索中の通信や全文同期は行わず、接続先Desktopの既存Roomキャッシュを読む。

- Task名、端末保存のCapture原文、作業記録本文、取得済みのNote・関連Capture本文が対象。
- 空白で区切った言葉をすべて含む部分一致。日本語、`%`、`_`、引用符は文字どおりに扱う。検索語は200文字まで。空欄は日付順の一覧。
- 1ページ50件。結果は日付の降順、種別、source IDで安定して並べる。同じ原資料が複数Taskや端末原文に現れても1件とし、未同期原文、本文version、取得時刻の順に保存版を選んでから検索する。
- 日付はTaskの更新日、作業記録の実施日、端末Captureの入力日、Note・関連本文の取得日。各結果に意味を表示する。
- Note・関連資料のThemeは関連Taskから判断する。Theme不明とThemeなしは区別する。
- 保存件数、未取得Note本文数、取得した日別記録の日数と部分取得日数を表示する。未取得のDesktop本文は検索されない。取得済み本文が途中までの場合はその範囲を明記する。

結果は既存のTask詳細・作業記録・Capture原文・関連資料本文を開く。
戻ると検索語、Theme、日付、ページ、結果のスクロールを復元する。
画面再生成でも同じ条件を復元する。

検索専用のDBや索引は作らず、Roomの変更通知から再検索する。
本文は64行ずつ読み、検索候補には抜粋と判定結果だけを保持する。
Task・作業記録の更新や削除、関連本文の取得・削除は既存キャッシュを通して反映する。
関連資料で参照先の削除を受信した場合、同じsourceの他Task側の保存本文も除く。
端末入力の正本は消さず、日別記録で既に受信したsourceの削除は既存の公開済み日キャッシュで表示を抑える。

確認済みの同一Desktopの401または閲覧APIの403は、対応する接続tokenを失効させ、関連閲覧キャッシュを破棄して検索を止める。
Task・端末原文・outboxは保持する。
アプリを開き直しても再接続までは検索しない。
他サーバーやプロキシ由来の401では失効させない。

## 検証

2026-09-08、隔離した読み取り専用AVDで以下を確認した。実端末と利用者データには接続していない。

- `:app:testDebugUnitTest`、`:app:assembleDebug`、`:app:assembleDebugAndroidTest`。
- `MobileLocalSearchDatabaseTest`：SQLite再接続後の4種検索、日本語・記号、日付・Theme、重複と新版、変更通知、削除、123件のページ継続。
- `MobileLocalSearchAccessTest`：401/403失効と再起動、再ペアリング、入力保持、他サーバー応答。
- `MobileLocalSearchUiTest`：検索中・0件・成功・失敗、検索語保持、Theme・日付・ページ・スクロールの再生成復元。
- `MobileLocalSearchTodayUiTest`：4種の既存画面への往復と検索位置保持、関連本文を追加通信せず開く。
- 既存の関連資料DB・Todayオフライン回帰テスト。
- compact 411dp、expanded 1200dpでUIテストと目視。表示、条件欄、結果スクロール、ページ操作を確認。スクリーンショットは検証worktreeの`output/search-552/`に保存。

実機Foldの折りたたみ遷移と大規模実データの性能測定は未検証。
