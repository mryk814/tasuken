# Tasken v0.1.46

## Codex対応と直接委任

- Windowsのタスク編集画面で、PCで利用できるClaude Code／GitHub Copilot／CodexからAIと関連作業先を選び、対話CLIを起動できるようにしました。
- 「AIを起動して渡す」は、Tasken上で確認したTask・AI・作業先に基づいてTaskをAI担当の作業中へ直接進めます。起動先AIが`start_task_work`を再提案する必要をなくし、開始承認の二重往復を省きました。
- CLIを開けなかった場合も開始記録は残り、同じAIと作業先から再試行できます。

## 安全境界

- 直接確定するのは、Tasken内で本人が押した作業開始だけです。外部MCPからの`start_task_work`と、途中経過・完了・blockedの報告は従来どおりProposal／Work Receiptを通り、Task完了には本人の確認が必要です。
- AIへの割当と作業開始は同じデータベース処理で完結させ、開始直後のTaskが「委任待ち」へ戻らないようにしました。
- 共有同期には確定した「作業中」だけを送り、同期先でもAI担当・開始時刻を保つようにしました。
- 作業先はTask／Themeに関連付いた実在ローカルフォルダに限定します。Tasken MCP設定は起動プロセスだけへ渡し、各AIのグローバル設定変更や権限確認の迂回は行いません。

## 検証範囲

- 対象のTask起動・作業開始・MCP境界テスト、実SQLite回帰テスト、typecheck、Windows x64 packageを確認しました。
- パッケージ版で、開始Proposalの採用、古いWork Receiptの衝突案内、最新版での再試行、Work Receiptの一回適用、人間レビュー表示までを確認しました。
- 分離したテストデータで、Claude Code／GitHub Copilot／Codexがインストール状況に応じて並び、Codexを選択しても作業先・Task・起動操作が崩れないことを実画面で確認しました。
- 実際の各CLIへタスクを渡して作業を完遂し、結果報告まで通す操作は、この変更の事前確認では実行していません。CLIの起動とAIの作業完了は別の状態です。
