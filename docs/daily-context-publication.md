# 日別の公開用Markdown

DebriefのActivityにある「公開用Markdown」から、対象日・記録当時のTheme・保存先を選び、プレビュー後に保存する。
OneDriveを使う場合は、同期対象のローカルフォルダーを選ぶ。
Taskenが確認するのはローカルへの書き込みまでであり、クラウド同期やM365 Copilotの索引更新は未確認として表示する。

保存先の `Tasken Context/Days/YYYY-MM-DD.md` と `.tasken-context.json` を管理する。
既存のTheme AI Packの固定7ファイルは変更しない。
公開物は読み取り専用の派生データで、編集内容をSQLiteの正本へ取り込まない。
同じWorkspace・タイムゾーンの管理フォルダーだけを更新し、外部で編集されたMarkdown、symlink/junction、未管理の既存フォルダーは上書きしない。

公開対象は共通のrecall queryと現在のM365公開policyで決める。
当時の名称・所属、操作日時と本人申告の実施日、予定・入力・AI報告・人間の採用・作業記録を区別する。
出典の現在revisionは当時の本文を再現する証拠ではない。
長文の全文と未同期入力は収録しない。
500件ずつ続きを取得し、最大100ページで打ち切った場合は部分取得として明示し、追加確認がなければ保存しない。

保存直前に公開内容を再構築し、プレビューのhashと一致しなければ停止する。
公開範囲を狭めた場合は、プレビューを更新して同じ日を再公開することでローカルの旧内容を置き換える。
再公開するまでは旧公開物が残る。クラウドや外部AI側の旧内容の削除は保証しない。
更新前にmanifestへ未完了状態を書き、Markdownをatomic置換した後に完了を記録する。
途中で失敗した場合は同じ日を再公開する。退避ファイルの削除失敗は成功扱いにしない。

検証は `rtk node scripts/run-electron-node.mjs --test tests/daily-context.test.mjs`。
隔離userDataで空状態、実施日付きの架空記録、保存、エラー時の入力保持、閉じた後のfocusを確認する。
2026-09-06の隔離Electron検証では、空状態・架空記録の保存・公開policy変更によるstale拒否・再公開による旧内容除去・再起動を確認した。
同じ架空記録を個人OneDriveの専用テストフォルダーへ保存し、ChromeのOneDrive Web表示で管理manifestと日別Markdownの到達、生成日時・本文・出典revisionの一致を確認した。
この確認は当日のテストファイルの同期を示すものであり、アプリからクラウド状態を観測する機能やM365 Copilotによる検索の確認ではない。
全文公開、自動更新はそれぞれ #546、#547 で扱う。

## 週・月・年から読む

日別の保存時に、同じ管理フォルダーの `README.md`、`Years/YYYY.md`、`Months/YYYY-MM.md`、`Weeks/YYYY-Www.md` も再生成する。
入口READMEから年、月または週、日別ファイル、日別に記載された型・ID・revisionの出典へ辿れる。
索引は公開済みmanifestの投影情報だけを使い、未公開の正本から名称や本文を補わない。
旧版で公開した日は「所属情報未収録（旧公開物）」と表示し、再公開後にTheme別の入口を収録する。

週は月曜始まりのISO週を使う。
2021-01-01は暦年2021年だが2020-W53に属し、その週は2020-12-28〜2021-01-03を含む。
日付はmanifestのタイムゾーンで選択済みの暦日であり、索引生成時に別のタイムゾーンへ変換しない。
公開済み日数に対して期間内の残りを未公開日数として示すため、進行中の月・年では未来の日も未公開に含まれる。

たとえば2020-12-31と2021-01-01に同じ作業記録を公開したfixtureでは、週の概要を次のように出力する。

```markdown
# 2020-W53

対象: 2020-12-28〜2021-01-03
公開日 2日 / 未公開日 5日 / 重複を除いた出典 1件
```

日別の行は「公開済み」「公開済み・収録0件」「部分公開・収録打切り」を区別し、除外件数・Theme範囲・生成日時・revisionを併記する。
予定・入力・作業記録を実績や作業時間として合算しない。
件数はsourceの型とIDで重複を除いた出典数である。
未公開や収録0件は、活動がなかったことを意味しない。

日別と索引の複数ファイルを同時にatomic置換することはできないため、管理manifestの `pending` が `null` で、保存処理が退避ファイルの削除警告なく成功したときだけ一式の更新完了と判断する。
中断時には更新前後のファイルが混在し得る。同じ日を再公開するまで振り返りの根拠に使わない。
再試行時は前回操作の管理対象tmp/bakをhashで確認して撤去する。外部変更などで由来を確認できないファイルや削除できないファイルが残る場合は停止する。
再公開は全管理索引を更新し、非公開化などで日別投影から除かれたTheme名も消す。
手動で撤去された管理日別ファイルは、次の公開時にmanifestと索引から除去する。
それに伴って不要になった週・月・年ファイルも撤去するが、利用者の別ファイルは保持する。
管理対象への外部編集を検出すると、日別ファイルを変更する前に停止する。
現在のpolicy変更を過去の公開日すべてへ自動反映する処理は #547 の対象であり、それまでは該当日を再公開する必要がある。

索引の検証は `rtk node scripts/run-electron-node.mjs --test tests/daily-context.test.mjs tests/period-context.test.mjs`。
fixtureで年跨ぎ・うるう日・Themeなし・部分公開・全相対リンク・非公開化・撤去・外部編集・連続中断からの再試行を確認する。
