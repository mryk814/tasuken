# デスクトップ画面の対応幅

Tasken の通常画面は、Windows 11 のノートPCと外部ディスプレイを往復しても、同じ正本データを無理なく扱えることを基準にする。

## 基準環境

- 優先基準: 1920 × 1200（WUXGA）のノートPC
- 広幅確認: 2560 × 1440（WQHD）の外部ディスプレイ
- Windowsの表示倍率を考慮し、実装と検証では実効CSS viewport 1280 × 800、1536 × 960も確認する

## 最小ウィンドウ幅

サポートする最小ウィンドウ幅は **980 × 680** とする（`src/main/index.ts` の `minWidth` / `minHeight` が正本）。

この幅で、次はすべて利用できることを条件にする。

- 左Sidebarのナビゲーションと現在の画面名
- 各画面の主操作
- 本文または一覧
- 各ペイン内のスクロール

表示倍率は本文だけに適用され最大1.3倍まで上げられるため、実効の作業幅は最小で約754pxになる。監査はこの実効幅まで含める。

## 狭幅レスポンシブ契約（#300）

1. **日本語ラベルを一文字ずつ縦積みにしない。** flex/gridの子は既定で内容幅より小さく潰れるため、操作要素と見出しには `word-break: keep-all` を効かせる。文字を縦に折り返して幅へ収めることを解決策にしない。
2. **幅が足りない場合の対応順**: 文言を減らす → ラベルを短くする → アイコン＋tooltipにする → overflow menuへ畳む → 段組みする。フォントサイズを一律に縮めない。
3. **ツールバーは `.toolbar-row` で行送りする。** 詰め込んで各操作を潰さない。
4. **低頻度操作は共通の `ToolbarOverflow`（`…`相当のメニュー）へ畳む。** メニューは幅で出し入れせず常設し、主要操作の順序と位置が幅で入れ替わらないようにする。
5. **メニューの挙動**: 表示切替（checkbox）は続けて操作できるよう開いたまま、一度きりの操作（`role="menuitem"`）は実行したら閉じる。Escと外側クリックで閉じる。
6. **画面全体の横スクロールを出さない。** Timelineや表のように本質的に横幅が必要なものだけ、そのペイン内でスクロールさせる。

## レイアウト方針

- 文字サイズを一律に縮めて情報を押し込まない。外枠、固定幅、余白、折り返しを先に調整する。
- 実効幅1680px以下では右のContext Paneを常設せず、編集Drawerは右側へ重ねて中央の作業幅を守る。
- 重ね表示のDrawerは、本文などDrawer外へ操作・フォーカスが移ったとき、変更を保存して閉じる。保存に失敗した場合は閉じず、入力を保持する。広幅の常設右レールでは自動で閉じない。
- 左Sidebarは利用者が畳めるようにし、端末ごとに状態を保存する。
- Sidebar切り替え、Taskenブランド、表示、ヘルプは40pxのカスタムタイトルバーへ集約する。Windows標準の最小化・最大化・閉じるは残す。
- 表示倍率は本文の作業領域だけに適用し、タイトルバーと拡大・縮小ボタンは100%の位置・大きさを保つ。倍率は端末ごとに保存する。
- Sidebarを畳んでもナビグループの見出し領域は高さを保ち、各アイコンの縦位置を変えない。Themeは色ボタンを残して移動可能にする。
- NotesとChat Refsは、WUXGAの実効幅でページ全体の横スクロールを発生させない。
- 一覧や本文のスクロールは、役割が明確な各ペインの内側に限定する。
- 2560 × 1440ではNotesとChat Refsの最大幅を1600pxまで広げる。ただし本文の読み幅を無制限には伸ばさない。

## 実動確認

NotesとChat Refsについて、1280 × 800、1536 × 960、1920 × 1200、2560 × 1440で次を確認する。

1. ページ全体に意図しない横スクロールがない。
2. 見出し、検索、絞り込み、主要操作が欠けず、必要な箇所だけ自然に折り返す。
3. 長いタイトル、URL、Theme名が隣の操作を押し出さず、省略表示または適切な折り返しになる。
4. Sidebarの展開・折り畳み後も選択中の画面とスクロール位置が保たれる。
5. Drawerを開いても中央レイアウトが再配置されず、閉じると元の作業位置へ戻る。
6. 実効幅1680px以下ではDrawer外の本文操作で変更が保存されて閉じ、1680px超では常設表示を維持する。
7. Sidebarを畳んでもナビ項目の縦位置が変わらず、Theme色ボタンから各Themeへ移動できる。
8. 表示倍率を連続で変更しても、タイトルバーと拡大・縮小ボタンの位置・大きさが変わらない。

### 狭幅監査（#300）

Today / Inbox / Timeline / Notes / Knowledge / Chat Refs / Artifacts / Sketch / Settings について、幅980・1120・1440、表示倍率1.0・1.3で次を確認する。

1. テキストの行ボックスを実測し、一文字ずつ縦積みになっている箇所がない。
2. 画面全体の横スクロールがない。
3. 主要操作がTabで到達でき、focusリングが出る。
4. overflow menuがEnterで開き、Escで閉じ、設定が保持される。

2026-08-06の監査では、Timelineツールバー（年度・前後3か月・完了タスク・依存線・イナズマ線・依存をつなぐ・全展開・全折りたたみ）、AI IOの`書き出す`見出し、Todayの`コピー`、Notesの操作ボタン群で縦積みを確認し、上記契約で解消した。
