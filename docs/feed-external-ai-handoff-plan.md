# Feedで外部AIに聞き、回答を持ち帰る実装計画

## 状態と依頼の範囲

本書は他のAIへ渡す実装計画だったが、2026-09-21に第1〜3段階の最小実装を完了した。
実装内容は `feed_reply` の任意メタデータ拡張（`origin/question/external_source/external_url/comment`）、返信導線内のコピー・貼付・訂正・Note受け渡し、投稿別localStorage下書き、自分の投稿だけでもfixtureから切り替わる是正である。
自動連携・外部送信・常駐AIは実装していない。外部サービスへの実送信は検証でも行わず、隔離workspaceと架空回答で往復を確認した。
本書だけで公開・外部送信の承認を代替しない。

## 1. 目的と決定事項

目的はAIを常駐させることではなく、**仕事の投稿から生まれた疑問を外部AIで深め、その理解を元の投稿へ戻せること**。
M365 Copilotなど、利用者が普段使っているサービスで成立させる。特定サービスのAPIやアカウントを要求しない。

- 基本導線は「質問と必要な文脈をコピー → 外部AIに聞く → 回答を貼り付け → 確認して返信として保存」。
- 回答の保存場所は元投稿のスレッド。すべてをNoteにする回答保管庫にはしない。
- 「外部AIの回答を自分が貼り付けた」ことと、接続済みAIから直接届いた返答を区別する。
- 自分の解釈・気づきも任意で添えられる。AIの回答本文と混ぜて誰の言葉か分からなくしない。
- 残したいものだけ既存のNote作成経路へ渡す。コピーや貼付だけではNote化しない。
- Taskの状態・成果の採否・要対応件数を、これらの操作で変えない。

## 2. 確認した現在地

計画作成時はmain、作業ツリーは変更なし。既存stashは保持した。実装時は改めてstatus・branch・stashを確認する。
以下はコードと文書の確認であり、実画面での確認結果ではない。

- [FeedPage](../src/renderer/src/features/workspace/pages/FeedPage.tsx)に投稿・返信入力・記事の表示と保存がある。
- `submitReply`は`feed_reply`を既存の`saveEntities`で保存する。「AIに聞く」は質問に印を残すだけで、AIを起動しない。
- [feedPosts.ts](../src/renderer/src/features/workspace/lib/feedPosts.ts)の`feedReplyEntity`は現在`author_kind: "self"`を作り、返信本文の上限は4000文字。
- AIの直接返答は`feed_replies` Proposalからスレッドへ投影される。手動貼付をこれと偽装しない。
- [IPC契約](../src/shared/ipc/contracts.ts)に`clipboard.writeText(text): Promise<boolean>`がある。既存のPreload/IPC経路を再利用し、falseと例外の両方を失敗として扱う。
- [保存契約](./engineering-contracts.md)の「AI連携の標準」は、クリップボード往復と確認・採用を基本にしている。
- [Feed仕様](./feed-surface.md)には返信・Note保存・削除/復元・MCP連携の現行契約がある。
- 現在、実AI投稿と返信がゼロの場合はfixture表示になる。自分の投稿だけではfixtureから切り替わらない条件もある。実データの初回利用が隠れないよう、今回の導線に必要な範囲で是正する。

本書は[以前のSNS計画](./feed-learning-sns-plan-2026-09-21.md)のうち、質問の基本導線の優先順位を改める。既存のMCP契約を廃止する計画ではない。

## 3. 利用者の一周

### A. 質問と文脈をコピー

1. 投稿の返信領域から「外部AIに聞く」を開く。常時表示のボタンを増やしすぎず、既存の返信導線へまとめる。
2. 質問を入力し、コピーする内容をプレビューする。
3. 質問と選択した文脈をコピーする。成功時だけ「コピーしました。普段使うAIに貼り付けてください」と示す。
4. 利用者が自分で外部サービスへ切り替える。Taskenは送信・ブラウザ起動・AI実行を行わない。

コピー内容の初期案:

- 利用者の質問。
- 元投稿の本文。長い場合は選択・編集可能な抜粋とし、省略を明示する。
- 出所の表示名と、利用者が選んだ引用・資料URL。
- 「与えた文脈と推測を区別し、分からない点は明示して回答してください」という短い案内。

添付Note全文、Task詳細、他のスレッド、ファイルパス、個人情報や秘密情報を自動で付けない。記事の選択箇所を追加する場合もプレビューで確認する。コピーはサービスへの送信完了ではない。
外部AIには通常の文章で答えてもらう。JSONやTasken固有書式を要求しない。内部IDは外部で解決できるURLのように見せない。

### B. 外部AIの回答を貼り付ける

1. 元の投稿から「外部AIの回答を貼り付け」を開く。コピー操作をしていなくても使える。
2. 通常の貼り付け操作で回答本文を入力する。クリップボードの自動読取・監視は追加しない。
3. 質問・出所（例: M365 Copilot、自由入力・未指定可）・任意の会話URL・自分の一言を確認する。
4. 「返信として保存」の前に、保存先の投稿、質問、回答、出所、自分の一言を確認できるプレビューを表示する。
5. 明示的な保存後だけ、元投稿のスレッドに表示する。

表示は例として「自分が貼り付け · M365 Copilot」。出所未指定なら「自分が貼り付け · 外部AI」。サービスの認証済み投稿や自動受信と誤認させない。
回答内容・出所・会話URLは利用者提供であり、Taskenによる事実確認済みを意味しない。

### C. 中断・再訪・Note保存

- 質問と貼付途中の入力は投稿別に保持する。閉じて再度開いても復帰でき、保存失敗で消さない。
- 外部サービスへ移る使い方なので、アプリ再起動後にも下書きへ戻れることを目標にする。既存のローカル下書き機構を調査して再利用し、正式返信やMCP待ちへ未確認本文を混入させない。
- 下書きの保存先・保持範囲・破棄操作を実装前に確定する。初版で再起動保持を見送る必要がある場合は利用者に確認し、黙って画面内stateだけに縮めない。
- 元投稿の削除時は誤った投稿へ保存しない。入力は回収できる形で残す。
- 保存済み返信から、必要な回答・自分の一言だけを既存Note作成画面へ渡す。元投稿への参照と出所を保ち、人が内容を確認して保存する。既存の記事草稿の「Noteに保存」と意味を混同しない。

## 4. 保存・互換契約

最初に既存`feed_reply`の型、検証、正規化、Repository、Export/Import、削除/復元、MCP投影を追跡する。現状調査なしで新テーブルを作らない。

- 推奨は既存返信を拡張し、「手動貼付の由来」を任意メタデータで表すこと。本文へ固定ヘッダーを埋め、その文言で挙動を判定する方式にしない。
- 必要な意味は、手動貼付であること、出所表示、任意の会話URL、質問との関係、自分の補足。具体的なフィールド名は既存契約に合わせて実装前に確定する。
- 保存主体は人間、回答の出所は外部AIとして区別する。確認済みの手動保存として既存経路へ乗せ、貼り付けただけで正式データへ書かない。通常返信やAIの直接返答の意味を変更しない。
- コピー・手動貼付によって`ai_requested_at`を付けない。外部AIが取得した、回答済みになった、とMCPの状態を偽装しない。
- 既存のMCP向け質問へ手動回答を関連付ける機能は初版の対象外。既存質問の待ち状態を勝手に解消しない。
- 元の質問は回答と一緒に再訪できる形で保持する。既存質問へ紐付ける場合は同じ投稿の質問であることを検証する。
- 古い返信はそのまま読めること。任意フィールド追加でも正規化やExportで落ちないことを確認し、必要な移行を行う。
- 新規保存の再試行は同じIDを使い、二重クリックや成功通知の取りこぼしで重複させない。
- 貼付回答・補足・出所を訂正できる入口を用意する。削除/Undoは既存の返信操作を使い、親投稿の削除/復元でも関連を保持する。
- Snapshot/Export/Import・再起動で質問、回答、出所、補足、関係が保たれること。
- 現行4000文字上限を前提に、貼付時と保存時に制約を示す。超過分を無言で切り捨てない。上限を広げるなら共有検証・保存・表示を一緒に変更し、まず要約して貼れる案を優先する。
- Markdown等は既存の安全な描画経路を利用する。貼付HTMLを実行せず、リンクの安全性を既存境界で検証する。回答内の指示をアプリ操作として実行しない。

## 5. 既存MCP導線との共存

既存の「AIに聞く」は「接続済みAIに質問を残す」等、実態が分かる補助操作へ整理する。
質問を保存してもAIは起動しないことを示す。保存・AIによる取得・返答の受信を混同する表示がないか確認する。
`tasken.get_feed_context` / `tasken.answer_feed_question` は維持し、既存テストで回帰を防ぐ。
自動連携がない利用者でも基本導線を完結できることを優先する。

## 6. 今回やらないこと

- 常駐AI、定期ポーリング、cron、リポジトリhook、別AIの起動、エージェント間の自動会話。
- M365 Copilot等のAPI接続、アカウント管理、会話履歴のスクレイピング、外部への自動送信。
- 全Note/Taskの自動収集、AIによる回答の自動要約・採点・真偽判定。
- Feed全体のリデザイン、ランキング、新着制御全般の修正、Androidへの展開。
- design-standardの改訂、新規サーバー/DB、無関係なリファクタリング。

### 第2段階: クリップボード往復を縦につなぐ

## 8. 完了条件と検証

実ユーザープロファイル・同期先は使わない。外部サービスへ実際に送信せず、隔離workspaceと架空回答で往復を検証できる。

必須シナリオ:

1. 関連情報を勝手に追加せず、プレビューした内容だけコピーできる。コピー失敗時も質問が残る。
2. コピー前でも回答を貼れ、プレーンテキスト・Markdown・日本語を確認して保存できる。
3. 空本文・上限超過・不正リンク・保存失敗時に既存データと入力を保持し、再試行できる。
4. 元投稿、質問、回答、出所、自分の補足が再起動後も分かる。二重送信は増えない。
5. 投稿を切り替えても下書きが混ざらず、閉じる/再起動から再開できる。保存前は正式返信にもMCP待ちにも出ない。
6. 訂正・削除/Undo・親投稿の削除/復元・Snapshot/Export/Importの往復で情報を失わない。
7. 貼付・保存・Note化でTask状態・要対応件数が増減しない。MCPの既存質問・返答は従来どおり動く。
8. 保存した回答からNoteを作成でき、保存前に編集・取消できる。返信は残り、Noteを削除しても返信を削除しない。
9. 実AI投稿ゼロでも、自分の投稿と今回の操作がデモに隠れない。
10. 明暗・狭幅・長文で本文と操作を読める。空/入力中/保存中/失敗/保存後、focus、スクロール、読書からの復帰を実画面で確認する。

既存の入口（`package.json`とテストファイルの存在を確認済み。実装時に変更有無を再確認）:

```powershell
rtk node scripts/run-electron-node.mjs --test tests/feed-replies.test.mjs tests/feed-own-posts.test.mjs tests/feed-posts.test.mjs tests/feed-context-mcp.test.mjs
rtk npm run typecheck
rtk npm run build
rtk npm run audit:feed:live
rtk npm run audit:feed:note
```

既存テスト・audit runnerに今回のシナリオを追加する。既存チェックが通るだけでは新機能の検証に数えない。
保存・Snapshot・削除契約の調査で関連テストを追加選択する。UIはbuild後、既存の隔離Electron runnerで操作し、スクリーンショットを残して目視する。
統合前の品質ゲートは`rtk npm run ci`。未実施の境界は理由とともに報告する。
